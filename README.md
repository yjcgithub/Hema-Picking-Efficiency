# 拣货效率计算统计工具

面向盒马门店的精益看板：把「门店视角：拣货单」的拣货明细（xlsx 导出 / 实时接口）解析入库，按**作业类型 / 拣货分区 / 人员 / 时段**计算效率指标并可视化。

三条核心设计原则：

- **口径唯一**：所有统计只在服务端 `compute.js` 实现，前端只渲染，避免前后端各写一套导致口径漂移
- **多来源同一口径**：xlsx 上传、服务端带 Cookie 取数、油猴脚本回传，三条路径都走同一套解析与统计
- **改完即生效**：前端无打包步骤，静态资源按内容哈希命名 + 入口 HTML 禁缓存，用户无需清缓存。

开发/维护向的分层、数据流与数据模型见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 功能特性

### 数据接入

| 模块 | 说明 |
|------|------|
| 拣货单上传 | 上传 xlsx，以文件内「拣货开始时间」的**日期集合**为时间维度：命中同维度历史记录则整条覆盖，否则新增一条 |
| 实时获取（服务端） | 由后端带 Cookie 逐页请求拣货单接口，按日期区间入库；支持「增量」（从最新页往回取，遇到整页单号都已入库即停） |
| 实时获取（油猴脚本） | UMS 登录态是 HttpOnly Cookie，脚本读不到；改为在 ums 页面内用登录态**同源**取数后回传后端 —— 后端无需 Cookie，也能自动同步 |
| 自动获取 | 服务端定时任务按设置的间隔自动增量获取「当天」数据，可设每日执行时段（如 07:00 ~ 22:30），时段外自动暂停 |
| 手动获取 | 顶栏「手动获取」按钮，一键增量获取当天数据，不用打开弹窗；与自动获取共用 **60 秒冷却**窗口 |
| 防风控 | 翻页随机停顿、自动间隔抖动、连续失败指数退避、取数冷却，详见 [实时获取与防风控](#实时获取与防风控) |
| 历史数据集 | 多数据集并存，可查看 / 切换 / 删除；覆盖时保留原 id，前端选中态不受影响 |

### 看板

| 模块 | 说明 |
|------|------|
| 效率总览 | KPI 卡片、作业类型 × 小时效率图、各小时效率趋势 |
| 分区 × 小时热力图 | 按拣货分区的逐小时效率热力图 |
| 人员透视 | 人员 × 小时效率透视（按前场合流 / 后场合流 / 一体化分块），带组内平均 / 中位数 |
| 细分明细 | 按作业类型、拣货分区双维度效率明细 |
| 人员分析 | 人员效率明细、效率分布箱线图、效率分档、稳定性榜（变异系数） |
| 行数统计 | 行数 TOP 10、行数分档（人数 / 行数双口径）、集中度（帕累托） |
| 工作时间图 | 由拣货单起止时间反推每人每日在岗时段，输出在岗率、最大空档等指标 |
| 超时统计 | 按「是否拣货超时」判定超时单，按「超时判责」细分堆叠柱状图（含每小时分布） |
| 分区设置 | 维护「拣货分区 → 前后场分区（作业类型）」映射，支持「忽略（排除统计）」，保存后自动重算全部历史数据集 |
| 统计范围 | 默认只展示数据集内最新一天，其余日期由顶栏日期下拉手动选择；顶栏同时给出当前文件的统计时间段 |
| 口径开关 | 顶栏「按工时加权 / 人均」统一切换 KPI 卡、透视分块（含小计 / 整体）、细分与人员表合计行、两张效率趋势图 |
| 表格排序 | 所有表格表头均可点击切换升 / 降序（空值恒排在末尾） |
| 内容导出 | 每张卡片支持「导出为图片 / 复制为图片」（html2canvas），透视卡片可按分类选择导出范围；IP（http）访问时提示剪贴板不可用并给出域名链接 |

## 技术栈

- **运行环境**：Node.js **>= 22.5.0**（依赖内置 `node:sqlite`，免原生编译）
- **后端**：Express 4 + `node:sqlite` + SheetJS `xlsx`
- **前端**：原生 JS + CSS（`HEMA` 全局命名空间 + IIFE），图表 ECharts 5.5.1 与 html2canvas 1.4.1 **均通过 CDN 引入**
- **内容哈希构建**：`server/build.js`（`web/` → `dist/`，无打包器）
- **测试**：Node.js 内置测试运行器（`node --test`）

## 快速开始

```powershell
# 1. 安装依赖
cd server
npm install

# 2. 启动服务（自动加载 server/.env）
npm start

# 3. 访问看板
#    默认端口 3001，BASE_PATH 为 /hpe 时：
```

数据库为空时页面显示空视图 —— 上传第一份拣货单 xlsx，或在「实时获取」里配置一次后开始统计（无内置示例数据）。

## 环境变量

由 `npm start` 通过 `--env-file-if-exists=.env` 加载，命令行中已有的同名变量优先。

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `3001` | 监听端口，需与 nginx `proxy_pass` 一致 |
| `BASE_PATH` | 空 | 反向代理子路径前缀，如 `/hpe`。设置后 `/hpe/api/latest` 与 `/api/latest` 均可用 |
| `ALLOW_ORIGIN` | `*` | CORS 允许来源，可按需收紧为前端域名 |
| `HEMA_DB_PATH` | `server/data/hema.db` | SQLite 库文件路径（测试用独立库） |
| `HEMA_STATIC` | `auto` | 静态资源托管方式，详见下表 |
| `STATIC_DIR` / `HEMA_WEB_DIR` | 空 | 指定前端目录绝对路径（优先级最高，用于前后端分离部署） |

`HEMA_STATIC` 取值：

| 值 | 行为 |
|----|------|
| `auto` | 启动时构建指纹资源到 `dist/` 并托管（构建失败回落源目录） |
| `dist` | 只托管已构建产物（需先 `npm run build`；缺 `dist` 时回落源目录） |
| `web` | 直接托管源目录（未指纹化，兜底） |
| `off` / `none` / `api` | 完全不托管前端，只提供 API（前端由 nginx / 1Panel 站点托管时用） |

未指定目录时按候选顺序自动探测含 `index.html` 的目录（同仓 `web/`、`../web`、`/web`、`/app/web` 等），找不到则只提供 API。详见 [CACHE.md](CACHE.md)。

## API 接口

均以 `/api` 为前缀（若配置了 `BASE_PATH`，则在前面拼接子路径）。错误响应统一为 `{ error: string }`。

### 数据集与设置

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 健康检查：数据集数量、`basePath`、静态托管方式，以及已实现的接口能力 `features`（油猴脚本自检用） |
| POST | `/api/upload?name=文件名.xlsx` | 上传拣货单。请求体为 xlsx 原始字节（`Content-Type: */*`，上限 100 MB），文件名也可用 `x-filename` 头传递。返回 `{ id, mode: 'create' \| 'overwrite', ...dataset }` |
| GET | `/api/datasets` | 数据集列表（不含完整 payload） |
| GET | `/api/latest?date=YYYY-MM-DD` | 最新数据集完整结果（无数据时 404）。默认只返回数据集内**最新一天**，其余日期用 `date` 指定 |
| GET | `/api/datasets/:id?date=YYYY-MM-DD` | 指定数据集完整结果（日期规则同上） |
| DELETE | `/api/datasets/:id` | 删除数据集，返回 `{ removed: 条数 }` |
| GET | `/api/settings` | 读取分区映射与忽略列表，并返回数据中出现过的分区清单 |
| POST | `/api/settings` | 保存映射与忽略列表，并**立即重算全部历史数据集** |

`POST /api/settings` 请求体：

```json
{
  "map":    { "AH 水产*A": "前场合流", "P 后场拣货区（标品）*P": "后场合流" },
  "ignore": ["BulkCommodityVirtualCode 大宗商品虚拟拣货分区"]
}
```

- `map` 的值必须是 `config.js` 中 `JOB_TYPES` 之一，非法值返回 400
- `ignore` 必须是字符串数组，非数组返回 400
- 返回 `{ ok, map, ignore, updated, skipped, failed }`；`skipped` 为缺少原始明细、需重新上传才能重算的数据集

### 实时获取（UMS）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/ums/config` | 配置与状态：`cookieSet`（只回布尔）、`build`、`num`、`numChoices`、`auto`、`agent`、`lastFetch`、`cooldown` |
| GET | `/api/ums/cookie` | 读取已保存的 Cookie 原文（仅点击「Cookie 设置」时按需调用，不放进轮询接口） |
| POST | `/api/ums/config` | 保存设置：`{ cookie? }`（传空字符串清除）、`{ num? }`（每页条数）、`{ auto? }`（开关 / 间隔 / 执行时段） |
| POST | `/api/ums/fetch` | 服务端带 Cookie 按日期区间取数入库：`{ startDate, endDate, incremental, cookie? }`。冷却中返回 429、已有任务返回 409 |
| POST | `/api/ums/agent/data` | 油猴脚本回传逐页结果入库：`{ startDate, endDate, pages[], complete?, reached? }` |
| POST | `/api/ums/known` | 判定这批拣货单号已入库多少条：`{ codes[] }` → `{ known, total }`（脚本增量追平判据） |

`GET /api/ums/config` 返回示例：

```json
{
  "cookieSet": true,
  "build": "e347969b",
  "num": 50,
  "numChoices": [50, 100, 200],
  "auto": {
    "enabled": true, "intervalMin": 5, "timeStart": "07:00", "timeEnd": "22:30",
    "at": "2026-09-29T02:09:46.064Z", "ok": true, "error": "", "records": 654, "added": 3,
    "failures": 0, "nextMin": 5, "nextAt": "2026-09-29T02:14:46.326Z"
  },
  "agent": null,
  "lastFetch": { "at": "…", "label": "实时接口 2026-09-29 ~ 2026-09-29（增量）", "mode": "merge", "added": 3, "records": 654, "id": 12 },
  "cooldown": { "sec": 60, "at": "2026-09-29T02:09:46.064Z", "waitSec": 42 }
}
```

`cooldown.waitSec > 0` 表示仍在冷却中；`auto.nextAt` 为排期好的下次自动获取时间（前端据此在触发前 10 秒显示倒计时）。

## 实时获取与防风控

### 两条取数路径

| 路径 | 依赖 | 适用 |
|------|------|------|
| 服务端带 Cookie | 先在弹窗里粘贴保存一次 Cookie（登录态过期后需重粘） | 浏览器不用开着，可在服务器常驻自动获取 |
| 油猴脚本同源取数（推荐） | 保持 ums 页面标签开着 | 无需配置 Cookie；脚本会把读到的 Cookie 一并保存到服务端 |

接口分页语义：`index` 是**页码**（0 起，0 = 倒序第一页 = 最新），`num` 是每页条数（页面可选 50 / 100 / 200），总页数 `ceil(totalNum / num)`，逐页 `index++`。

入库口径与上传完全一致：

- 整段抓取**完整**（跑到 `totalNum`）→ 按抓取日期集合整条替换当天/该区间的旧明细，避免与手动上传的同单重复计数
- **增量**抓取（遇到整页单号都已入库即停）→ 按「拣货单号 + 拣货分区」合并，只并入新增明细
- 只有**实时接口 / 脚本来源**的明细参与「增量追平」判定

### 自动获取

服务端每 5 秒检查一次排期，按设置的间隔自动增量获取「当天」数据；可设置每日执行时段（当天时间点，如 07:00 ~ 22:30），时段外暂停不请求。

### 防风控措施

| 措施 | 参数（`server/config.js`） | 说明 |
|------|---------------------------|------|
| 翻页停顿 | `UMS_PAGE_GAP_MIN_MS` / `UMS_PAGE_GAP_MAX_MS`（300 / 900） | 逐页请求之间随机停顿 300~900ms |
| 间隔抖动 | `UMS_INTERVAL_JITTER`（0.15） | 自动获取间隔 ±15% 随机抖动，避免固定时刻规律打点 |
| 失败退避 | `UMS_BACKOFF_MAX_MIN`（60） | 连续失败按 `间隔 × 2^失败次数` 退避，上限 60 分钟，成功即清零 |
| 取数冷却 | `UMS_FETCH_COOLDOWN_SEC`（60） | 手动 / 自动 / 脚本同步**共用**同一冷却窗口，两次取数不得少于 60 秒 |

界面上的体现：顶栏角标只显示自动获取开关状态（`自动获取：开 / 关`），临近触发前 10 秒追加倒计时（`· 8 秒后获取`）；「手动获取」按钮在冷却中禁用并显示 `冷却 N 秒`。

### Cookie 失效怎么办

登录态过期时（接口返回登录页 / HTTP 401 / 403 / 非 JSON），页面会提示：

> Cookie 已失效（登录态过期）：请打开盒马工作台页面，点右下角插件面板里的「立即同步」手动同步一次，脚本会重新读取并保存 Cookie

也可以直接在「实时获取」弹窗的「接口 Cookie」里重新粘贴一次 Cookie。

### 油猴脚本安装

1. Tampermonkey 中新建脚本，粘贴 `userscript/` 下**任选其一**：
   - `hema-pick-sync.user.js` —— 只有同步面板
   - `选中文本生成条码For Hema(拖拽跟随) CODE-128.js` —— 条码脚本 + 内置同步面板（v4.6，UI 在「条码设置」里）
2. 打开盒马工作台 / UMS 页面，面板会自动出现
3. 「后端地址」填本服务地址（如 `http://localhost:3001/hpe`，无子路径则 `http://localhost:3001`），点「立即同步」验证连通
4. 脚本会先 `fetch`（自动带 Cookie），被 CORS 拦则降级 `GM_xmlhttpRequest`；取数结果回传 `/api/ums/agent/data`，读到的 Cookie 同步保存到服务端（`POST /api/ums/config`）
5. 保持该标签页开着即可；登录态过期时重新登录一次

## 上传文件格式要求

取工作表中名为 `data` 的表（不存在则取第一个），第一行为表头。**必需列**（定义于 `server/config.js`）：

```
拣货单号、拣货人、拣货开始时间、拣货完成时间、拣货行数、拣货分区、拣货单类型
```

**可选列**：`是否拣货超时`、`超时判责`（缺列时不做超时统计，也不阻塞上传）。

解析与校验规则：

- **时间字段**：`拣货开始时间` 支持 `YYYY-MM-DD HH:mm[:ss]` 字符串或 Excel 日期序列号，缺少该列直接报错
- **异常处理**：任一时间单元格无法解析 → 终止上传并提示具体行号；整列无有效时间 → 终止上传
- **丢弃规则**：缺少拣货人或缺少时间的明细行按「丢弃」处理，计入 `meta.dropped`，不参与统计
- **门店鉴别**：拣货单号前缀非门店编码（`STORE_CODE = 20005`）的其它门店明细整行排除，计入 `meta.otherStore`
- **时间维度**：取文件中**全部明细**的日期集合（不受「忽略分区」影响）作为拣货单标识，用于覆盖 / 新增匹配
- **覆盖规则**：同时间维度命中历史记录则整条覆盖（保留原 id）；同维度存在多条历史记录时，仅覆盖最新一条

## 核心概念与统计口径

### 效率

```
效率（行/h） = Σ拣货行数 ÷ Σ拣货时长(h)
拣货时长     = 拣货完成时间 − 拣货开始时间
```

### 作业类型

```
IF 拣货单类型 = 「拣打一体」  →  「一体化」
否则                        →  前后场映射(拣货分区)
未命中映射                   →  「未匹配分区」
```

映射即顶栏「分区设置」中维护的「拣货分区 → 前后场分区」表，未保存过时使用 `config.js` 中的 `DEFAULT_FRONT_BACK_MAP`。

### 明细的四种归宿

| 状态 | 含义 |
|------|------|
| 有效 | 参与全部统计 |
| 已忽略 | 拣货分区在「忽略分区」列表中 → **完全排除出统计**，仅记为 `meta.ignored`，明细原样保存在库中 |
| 丢弃 | 缺拣货人或缺时间 → 记为 `meta.dropped` |
| 其它门店 | 拣货单号前缀不是门店编码 → 记为 `meta.otherStore` |

> 忽略判定按**分区**进行，先于作业类型判定，因此「拣打一体」的被忽略分区不会混入「一体化」；取消忽略后重算即可恢复。

### 两种效率口径

| 口径 | 计算方式 | 适用范围 |
|------|---------|---------|
| 按工时加权 | Σ拣货行数 ÷ Σ拣货时长(h) | 默认 |
| 人均 | 各人效率的算术平均（忽略该时段无记录的人） | 顶栏开关切换 |

顶栏开关统一切换所有聚合效率：KPI 卡、透视分块（含小计与「整体」）、细分表与人员表的合计行、效率趋势图与作业类型 × 小时图。
人员级数字（各人自己的效率、「效率分布」卡、稳定性榜、工作时间图）不受开关影响。

### 其他口径

- **稳定性**：取该人记录最多的作业类型，用其每小时效率计算变异系数（标准差 ÷ 平均）。跨作业类型基准差异大（后场约 250、前场约 70），故不混算，避免把「多类型支援」误判为不稳定
- **工作时间图**：每笔拣货单按其真实起止时间 `[拣货开始时间, 拣货完成时间]`（当日 00:00 起的分钟数）取区间；上一笔结束到下一笔开始的间隔 ≤ 2 分钟时视为连续作业并合并为一段（重叠亦接续），故色块宽度 = 真实段长，tooltip 显示该段的起止时刻、时长、行数、拣货单数与该段效率。在岗率 = Σ段长 ÷ (末段结束 − 首段开始)
- **分档区间**：效率分档 `[0,60) [60,90) [90,120) [120,180) [180,240) ≥240`；行数分档 `[0,100) [100,250) [250,500) [500,800) ≥800`（固定档位便于跨数据集对比）
- **超时**：`是否拣货超时` 等于「是」的明细计为超时，按 `超时判责` 取值分组（为空归入「未填判责」）堆叠展示；文件无该列时整张卡片隐藏
- **展示日期**：默认只展示数据集内最新一天（隔天不显示前天），其余日期由顶栏日期下拉手动选择；顶栏最顶端同时给出当前文件的统计时间段（文件内最早开始 → 最晚结束）

## 部署

前置：Node.js ≥ 22.5（如需 `node:sqlite` 的完整能力，建议使用官方 22 LTS 或更高版本）。

```bash
cd server
npm install --omit=dev
nohup npm start > server.log 2>&1 &
```

nginx 子路径反向代理示例（两种写法均受支持，服务端已做路径归一化）：

```nginx
# 写法一：不剥前缀
location /hpe/ {
    proxy_pass http://127.0.0.1:3001;
}

# 写法二：剥掉前缀（proxy_pass 末尾带 /）
location /hpe/ {
    proxy_pass http://127.0.0.1:3001/;
}
```

**注意**：前端 `web/assets/js/config.js` 中的 `API_BASE` 按访问来源自动选择后端地址，并写入了固定的域名 / IP（`api.yjmc.xyz`、`8.137.63.172`）；油猴脚本里的后端地址也需在面板中填写。部署到其他环境时需调整这两处。

### 静态资源发布与缓存

前端源码放在 `web/`，发布时由 `server/build.js` 构建到 `dist/` 并托管：资源文件名插入内容哈希（`app.js → app.e347969b.js`），入口 HTML 保持文件名但禁止缓存。

| 资源 | 响应头 | 效果 |
|------|--------|------|
| `index.html` | `Cache-Control: no-store` | 每次访问都回源，永远拿到最新 HTML 与最新指纹路径 |
| `*.{hash8}.js/css/png…` | `public, max-age=31536000, immutable` + 强 ETag | 内容没变零请求；内容一变文件名即变，必然重新下载 |
| 其它（`manifest.json` 等） | `no-cache` | 可缓存但每次协商，未变返回 304 |

```powershell
cd server
npm start            # HEMA_STATIC=auto（默认）：启动时自动重建 dist/ 后托管
# 或
npm run build        # 显式构建，打印 原始路径 -> 指纹路径 清单
```

改完 `web/` 下的文件后**重启服务**即可；API 响应统一带 `no-store`，避免浏览器轮询命中 304 空响应。反向代理（nginx / Apache）需**透传上游缓存头且不要缓存 HTML**，完整配置示例、浏览器验证步骤与故障排查见 [CACHE.md](CACHE.md)。

## 常见问题

**Q：请求返回 404 且提示「路径未匹配」？**
反向代理子路径与 `BASE_PATH` 不一致。按响应中的 `hint` 处理：要么用 `BASE_PATH=前缀` 启动服务，要么把 nginx 的 `proxy_pass` 改为末尾带 `/` 的形式。

**Q：修改了前端文件但没有生效？**
前端静态资源按内容哈希命名，入口 HTML 为 `no-store`，正常刷新即可加载最新版本。注意两点：① `HEMA_STATIC=auto` 时构建发生在**服务启动阶段**，改完 `web/` 下的文件后需**重启服务**（或先 `npm run build`）；② 修改 `server/*.js` 后**必须重启服务**。若顶部角标提示「有新版本 · 点击刷新」，说明页面运行的 JS 与后端最新构建不一致，点一下即可。

**Q：实时获取失败，提示接口返回 HTTP 404 / 非 JSON？**
多半是接口域名不对。前端页面域是 `portalpro.hemaos.com`，而接口域是 `ums.hemaos.com`，脚本与服务端都必须请求接口域。此外若响应是 nginx 的 HTML 404，说明后端服务本身没起来或反向代理路径不对，可先访问 `/api/health` 自检（返回的 `features` 用于识别后端是否为旧版本）。

**Q：自动获取没执行？**
依次检查：① 是否保存了 Cookie（未保存时弹窗里会提示）；② 自动获取开关与间隔；③ 是否在当前设置的执行时段内；④ 是否处于取数冷却窗口内；⑤ 连续失败进入退避时，弹窗会显示「N 分钟后重试」。

**Q：Cookie 失效怎么恢复？**
打开盒马工作台页面，点右下角插件面板里的「立即同步」手动同步一次，脚本会重新读取并保存 Cookie；也可在「实时获取」弹窗里重新粘贴。

**Q：保存分区设置后部分数据集没有更新？**
早期数据集未保存原始明细，无法重算，会出现在返回值的 `skipped` 中，重新上传对应文件即可。

**Q：上传或重算报「无数据可统计」？**
所有有效明细的分区都在「忽略分区」列表中。先在「分区设置」中取消忽略再重试。

**Q：测试会不会影响线上数据？**
不会。测试通过 `HEMA_DB_PATH` 指向临时库，结束后自动清理。

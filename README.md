# 拣货效率计算统计工具

从盒马门店「门店视角：拣货单」导出文件（xlsx）解析拣货明细，按作业类型 / 分区 / 人员 / 时段计算效率指标，并以看板形式呈现的可视化系统。

- **服务端**：解析 xlsx、计算全部统计口径、SQLite 保存历史数据集、托管前端静态文件
- **前端**：纯静态页面（源码无需构建，发布时由 `server/build.js` 生成内容哈希指纹）
- **口径唯一**：所有统计在服务端 `compute.js` 中实现，前端只负责渲染，避免前后端各写一套导致口径漂移
- **改完即生效**：静态资源按内容哈希命名 + 入口 HTML 禁缓存，用户无需手动清缓存，详见 [CACHE.md](CACHE.md)

## 功能特性

| 模块 | 说明 |
|------|------|
| 拣货单上传 | 上传 xlsx，以文件内「拣货开始时间」的**日期集合**为时间维度：命中同维度历史记录则整条覆盖，否则新增一条 |
| 历史数据集 | 多数据集并存，可查看 / 切换 / 删除；覆盖时保留原 id，前端选中态不受影响 |
| 效率总览 | KPI 卡片、作业类型 × 小时 效率图、各小时效率趋势 |
| 人员透视 | 人员 × 小时效率透视（按前场合流 / 后场合流 / 一体化分块），带组内平均 / 中位数 |
| 细分明细 | 按作业类型、拣货分区双维度效率明细 |
| 人员分析 | 人员效率明细、效率分布箱线图、效率分档、稳定性榜（变异系数） |
| 行数统计 | 行数 TOP 10、行数分档（人数 / 行数双口径）、集中度（帕累托） |
| 工作时间图 | 由拣货单起止时间反推每人每日在岗时段，输出在岗率、最大空档等指标 |
| 超时统计 | 按「是否拣货超时」判定超时单，按「超时判责」细分堆叠柱状图（含每小时分布） |
| 分区设置 | 维护「拣货分区 → 前后场分区（作业类型）」映射，支持「忽略（排除统计）」，保存后自动重算全部历史数据集 |
| 统计范围 | 顶栏最顶端显示当前文件的统计时间段；多天文件只显示数据集内最新一天，其余日期由顶栏日期下拉手动选择 |
| 口径开关 | 顶栏「按工时加权 / 人均」统一切换 KPI 卡、透视分块（含小计 / 整体）、细分与人员表合计行、两张效率趋势图 |
| 表格排序 | 所有表格表头均可点击切换升 / 降序（空值恒排在末尾） |
| 内容导出 | 每张卡片支持「导出为图片 / 复制为图片」（html2canvas），透视卡片可按分类选择导出范围；IP（http）访问时提示剪贴板不可用并给出域名链接 |

## 技术栈

- **运行环境**：Node.js **>= 22.5.0**（依赖内置 `node:sqlite`，免原生编译）

- **前端**：原生 JS + CSS，图表 ECharts 5.5.1 与 html2canvas 1.4.1 **均通过 CDN 引入**
- **测试**：Node.js 内置测试运行器（`node --test`）

## 环境变量

由 `npm start` 通过 `--env-file-if-exists=.env` 加载，命令行中已有的同名变量优先。

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `3001` | 监听端口，需与 nginx `proxy_pass` 一致 |
| `BASE_PATH` | 空 | 反向代理子路径前缀，如 `/hpe`。设置后 `/hpe/api/latest` 与 `/api/latest` 均可用 |
| `ALLOW_ORIGIN` | `*` | CORS 允许来源，可按需收紧为前端域名 |
| `HEMA_DB_PATH` | `server/data/hema.db` | SQLite 库文件路径（测试用独立库） |
| `HEMA_STATIC` | `auto` | 静态资源托管方式：`auto` 启动时构建指纹资源到 `dist/` 并托管（失败回落源目录）；`dist` 只托管已构建产物（需先 `npm run build`）；`web` 直接托管源目录（未指纹化兜底）。详见 [CACHE.md](CACHE.md) |

## API 接口

均以 `/api` 为前缀（若配置了 `BASE_PATH`，则在前面拼接子路径）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 健康检查，返回数据集数量与当前 `basePath` |
| POST | `/api/upload?name=文件名.xlsx` | 上传拣货单。请求体为 xlsx 原始字节（`Content-Type: */*`，上限 100 MB），文件名也可用 `x-filename` 头传递。返回 `{ id, mode: 'create' \| 'overwrite', ...dataset }` |
| GET | `/api/datasets` | 数据集列表（不含完整 payload） |
| GET | `/api/latest?date=YYYY-MM-DD` | 最新数据集完整结果（无数据时 404）。默认只返回数据集内**最新一天**，其余日期用 `date` 指定 |
| GET | `/api/datasets/:id?date=YYYY-MM-DD` | 指定数据集完整结果（日期规则同上） |
| DELETE | `/api/datasets/:id` | 删除数据集，返回 `{ removed: 条数 }` |
| GET | `/api/settings` | 读取分区映射与忽略列表，并返回数据中出现过的分区清单 |
| POST | `/api/settings` | 保存映射与忽略列表，并**立即重算全部历史数据集** |

`POST /api/settings` 请求体：

```json
{
  "map":    { "AH 水产*A": "前场合流", "P 后场拣货区（标品）*P": "后场合流" },
  "ignore": ["BulkCommodityVirtualCode 大宗商品虚拟拣货分区"]
}
```

- `map` 的值必须是 `config.js` 中 `JOB_TYPES` 之一，非法值返回 400
- `ignore` 必须是字符串数组，非数组返回 400
- 返回 `{ ok, map, ignore, updated, skipped, failed }`；`skipped` 为缺少原始明细、需重新上传才能重算的数据集

## 上传文件格式要求

取工作表中名为 `data` 的表（不存在则取第一个），第一行为表头。**必需列**（定义于 `server/config.js`）：

```
拣货单号、拣货人、拣货开始时间、拣货完成时间、拣货行数、拣货分区、拣货单类型
```

**可选列**：`是否拣货超时`、`超时判责`（缺列时不做超时统计，也不阻塞上传）。

解析与校验规则：

- **时间字段**：`拣货开始时间` 支持 `YYYY-MM-DD HH:mm[:ss]` 字符串或 Excel 日期序列号，缺少该列直接报错
- **异常处理**：任一时间单元格无法解析 → 终止上传并提示具体行号；整列无有效时间 → 终止上传
- **丢弃规则**：缺少拣货人或缺少时间的明细行按「丢弃」处理，计入 `meta.dropped`，不参与统计
- **时间维度**：取文件中**全部明细**的日期集合（不受「忽略分区」影响）作为拣货单标识，用于覆盖 / 新增匹配
- **覆盖规则**：同时间维度命中历史记录则整条覆盖（保留原 id）；同维度存在多条历史记录时，仅覆盖最新一条

## 核心概念与统计口径

### 效率

```
效率（行/h） = Σ拣货行数 ÷ Σ拣货时长(h)
拣货时长     = 拣货完成时间 − 拣货开始时间
```

### 作业类型

```
IF 拣货单类型 = 「拣打一体」  →  「一体化」
否则                        →  前后场映射(拣货分区)
未命中映射                   →  「未匹配分区」
```

映射即顶栏「分区设置」中维护的「拣货分区 → 前后场分区」表，未保存过时使用 `config.js` 中的 `DEFAULT_FRONT_BACK_MAP`。

### 明细的三种归宿

| 状态 | 含义 |
|------|------|
| 有效 | 参与全部统计 |
| 已忽略 | 拣货分区在「忽略分区」列表中 → **完全排除出统计**，仅记为 `meta.ignored`，明细原样保存在库中 |
| 丢弃 | 缺拣货人或缺时间 → 记为 `meta.dropped` |

> 忽略判定按**分区**进行，先于作业类型判定，因此「拣打一体」的被忽略分区不会混入「一体化」；取消忽略后重算即可恢复。

### 两种效率口径

| 口径 | 计算方式 | 适用范围 |
|------|---------|---------|
| 按工时加权 | Σ拣货行数 ÷ Σ拣货时长(h) | 默认 |
| 人均 | 各人效率的算术平均（忽略该时段无记录的人） | 顶栏开关切换 |

顶栏开关统一切换所有聚合效率：KPI 卡、透视分块（含小计与「整体」）、细分表与人员表的合计行、效率趋势图与作业类型 × 小时图。
人员级数字（各人自己的效率、「效率分布」卡、稳定性榜、工作时间图）不受开关影响。

### 其他口径

- **稳定性**：取该人记录最多的作业类型，用其每小时效率计算变异系数（标准差 ÷ 平均）。跨作业类型基准差异大（后场约 250、前场约 70），故不混算，避免把「多类型支援」误判为不稳定
- **工作时间图**：每笔拣货单按其真实起止时间 `[拣货开始时间, 拣货完成时间]`（当日 00:00 起的分钟数）取区间；上一笔结束到下一笔开始的间隔 ≤ 2 分钟时视为连续作业并合并为一段（重叠亦接续），故色块宽度 = 真实段长，tooltip 显示该段的起止时刻、时长、行数、拣货单数与该段效率。在岗率 = Σ段长 ÷ (末段结束 − 首段开始)
- **分档区间**：效率分档 `[0,60) [60,90) [90,120) [120,180) [180,240) ≥240`；行数分档 `[0,100) [100,250) [250,500) [500,800) ≥800`（固定档位便于跨数据集对比）
- **超时**：`是否拣货超时` 等于「是」的明细计为超时，按 `超时判责` 取值分组（为空归入「未填判责」）堆叠展示；文件无该列时整张卡片隐藏
- **展示日期**：默认只展示数据集内最新一天（隔天不显示前天），其余日期由顶栏日期下拉手动选择；顶栏最顶端同时给出当前文件的统计时间段（文件内最早开始 → 最晚结束）

```bash
cd server
```

nginx 子路径反向代理示例（两种写法均受支持，服务端已做路径归一化）：

```nginx
# 写法一：不剥前缀
```

### 静态资源发布与缓存

前端源码放在 `web/`，发布时由 `server/build.js` 构建到 `dist/` 并托管：资源文件名插入内容哈希（`app.js → app.c9005a48.js`），入口 HTML 保持文件名但禁止缓存。

| 资源 | 响应头 | 效果 |
|------|--------|------|
| `index.html` | `Cache-Control: no-store` | 每次访问都回源，永远拿到最新 HTML 与最新指纹路径 |
| `*.{hash8}.js/css/png…` | `public, max-age=31536000, immutable` + 强 ETag | 内容没变零请求；内容一变文件名即变，必然重新下载 |
| 其它（`manifest.json` 等） | `no-cache` | 可缓存但每次协商，未变返回 304 |

```powershell
cd server
npm start            # HEMA_STATIC=auto（默认）：启动时自动重建 dist/ 后托管
# 或
npm run build        # 显式构建，打印 原始路径 -> 指纹路径 清单
```

改完 `web/` 下的文件后**重启服务**即可，用户无需手动清缓存。反向代理（nginx / Apache）需**透传上游缓存头且不要缓存 HTML**，完整配置示例、浏览器验证步骤与故障排查见 [CACHE.md](CACHE.md)。

## 常见问题

**Q：请求返回 404 且提示「路径未匹配」？**
反向代理子路径与 `BASE_PATH` 不一致。按响应中的 `hint` 处理：要么用 `BASE_PATH=前缀` 启动服务，要么把 nginx 的 `proxy_pass` 改为末尾带 `/` 的形式。

**Q：修改了前端文件但没有生效？**
前端静态资源按内容哈希命名，入口 HTML 为 `no-store`，正常刷新（无需清缓存、无需 Ctrl+F5）即可加载最新版本。注意两点：① `HEMA_STATIC=auto` 时构建发生在**服务启动阶段**，改完 `web/` 下的文件后需**重启服务**（或先 `npm run build`）；② 修改 `server/*.js` 后**必须重启服务**。若仍不生效，按 [CACHE.md](CACHE.md) 的「故障排查」逐项检查（多为 nginx / CDN 覆盖了上游 `Cache-Control`）。

**Q：保存分区设置后部分数据集没有更新？**
早期数据集未保存原始明细，无法重算，会出现在返回值的 `skipped` 中，重新上传对应文件即可。

**Q：上传或重算报「无数据可统计」？**
所有有效明细的分区都在「忽略分区」列表中。先在「分区设置」中取消忽略再重试。

**Q：测试会不会影响线上数据？**
不会。测试通过 `HEMA_DB_PATH` 指向临时库，结束后自动清理。
